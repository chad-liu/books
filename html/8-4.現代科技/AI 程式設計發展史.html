AI 程式設計發展史（History of AI-Assisted Programming）

AI 程式設計的發展史，是人工智慧從「協助分析程式」，逐漸進步到「自動產生程式碼」，再進一步發展成「能夠規劃、撰寫、測試與修改程式的 AI Agent」的歷史。

早期的程式設計完全依賴人類工程師，後來出現自動程式生成、智慧型程式補全、機器學習程式碼分析，直到今天，人類可以用自然語言描述需求，讓 AI 協助開發完整軟體。

這段歷史可以分成八個階段：

一、AI 程式設計發展大事記

第一階段：人工智慧與自動程式設計的萌芽（1950～1960年代）

這個階段的主要目標，是讓電腦不只是執行人類輸入的指令，也能協助解決問題、推導邏輯及產生程式。

時間重要事件發展意義
1950年艾倫・圖靈提出機器智慧的討論為機器能否展現智慧建立重要思考基礎
1956年達特茅斯人工智慧研討會人工智慧（AI）正式成為重要研究領域
1958年LISP 語言誕生成為早期 AI 研究的重要程式語言
1959年約翰・麥卡錫推動 AI 研究推動符號推理與人工智慧程式設計
1960年代自動定理證明與程式合成研究開始探索由電腦自動推導解題步驟
1966年Joseph Weizenbaum 開發 ELIZA展現電腦透過文字與人類對話的可能性
1969年SHRDLU 研究計畫開始展現自然語言理解與簡單指令執行能力

這個階段的重要觀念：

  • 符號人工智慧：利用邏輯符號與規則模擬人類思考。
  • 自動推理：讓電腦依照邏輯規則推導答案。
  • 自動程式合成：研究如何由問題描述產生可執行的程式。

這個時期的 AI 還不能像今天一樣直接替工程師完成大型軟體，但已經建立了自動化程式設計的理論基礎。

第二階段：專家系統與自動程式生成（1970～1980年代）

這個階段的 AI 開始利用專業知識與規則，協助人類解決特定領域的問題。

時間重要事件發展意義
1970年PROLOG 語言開始發展以邏輯規則及事實進行推理
1972年PROLOG 正式發展成為邏輯程式設計的重要代表
1970年代MYCIN 專家系統發展展示以知識規則協助專業決策的能力
1970年代程式自動生成研究持續發展探索從規格描述產生程式
1980年代專家系統商業化AI 開始應用於企業及工業領域
1983年CLIPS 專家系統工具開始發展讓知識規則系統更容易建立
1986年神經網路反向傳播方法受到重視為後來機器學習與深度學習奠定基礎

代表性技術：

  1. 專家系統（Expert System）：把專家的知識轉換成電腦可以執行的規則。
  2. 邏輯程式設計（Logic Programming）：讓電腦根據事實與規則推導結果。
  3. 程式生成（Program Generation）：嘗試讓電腦從較高層次的描述產生程式碼。

不過，早期專家系統大多只能處理特定問題，無法像現代 AI 一樣理解各種不同的程式需求。

第三階段：機器學習與智慧型程式分析（1990～2000年代）

這個階段的重大轉變，是 AI 不再只依靠人類事先設定的規則，而是開始從大量資料中學習。

時間重要事件發展意義
1990年代機器學習逐漸成熟電腦開始從資料中學習規律
1995年支援程式開發的智慧型 IDE 功能逐漸普及自動補全、語法檢查及除錯工具發展
1997年IBM Deep Blue 擊敗西洋棋世界冠軍卡斯帕洛夫展現電腦在特定複雜問題上的強大能力
1998年Java IDE 與程式分析工具發展提升大型軟體開發效率
2001年機器學習應用擴大AI 開始廣泛應用於分類、預測與模式辨識
2000年代靜態程式分析與自動測試工具成熟開始利用自動化技術協助發現程式錯誤

這個階段的主要特色：

  • 自動補全：根據程式上下文預測可能的程式碼。
  • 靜態分析：在程式執行之前檢查潛在錯誤。
  • 自動除錯：協助尋找程式中的問題。
  • 機器學習：讓電腦從程式碼與使用資料中學習規律。

第四階段：深度學習與程式碼智慧化（2010～2019年）

這是 AI 程式設計的重要轉折期。深度學習讓電腦開始能夠分析程式碼的結構，並逐漸具備程式碼生成能力。

時間重要事件發展意義
2012年AlexNet 在 ImageNet 競賽取得重大突破深度學習進入快速發展階段
2015年TensorFlow 開源發布推動機器學習與深度學習開發
2016年AlphaGo 擊敗李世乭展現深度學習與強化學習的能力
2017年Transformer 架構論文發表為大型語言模型與程式碼生成奠定重要基礎
2018年BERT 模型發表推動自然語言理解技術
2019年GPT-2 發表展現大型語言模型生成文字的能力
2019年CodeBERT 等程式碼理解研究逐漸發展AI 開始更深入理解程式碼與自然語言的關係

重要突破：Transformer

Transformer 是這個時期最重要的技術之一。

它能夠分析一段文字中不同部分的關聯，因此不只能處理一般文章，也能分析程式碼中變數、函式、語法及上下文之間的關係。

例如，人類輸入：

「請寫一個計算兩個數字總和的 Python 函式。」

AI 可以逐漸學會將這段自然語言轉換成程式碼。

第五階段：大型語言模型與 AI 程式助理（2020～2023年）

這是 AI 程式設計真正走入一般開發者工作環境的時期。

大型語言模型（LLM）能夠從大量文字及程式碼中學習，逐漸具備理解程式需求、生成程式碼、解釋錯誤及轉換程式語言的能力。

時間重要事件發展意義
2020年OpenAI 發表 GPT-3大型語言模型展現依照文字指令完成不同工作的能力
2021年OpenAI 發表 Codex專門針對程式碼訓練的模型，可以將自然語言轉換成程式碼
2021年6月GitHub Copilot 技術預覽推出AI 開始在程式編輯器中即時建議及補全程式碼
2022年6月GitHub Copilot 正式推出AI 程式助理開始成為一般開發者可使用的商業工具
2022年DeepMind 發表 AlphaCodeAI 在競賽程式設計問題上展現能力
2022年11月ChatGPT 正式推出一般使用者可以透過對話要求 AI 撰寫及解釋程式
2023年3月GPT-4 發表複雜程式理解、推理及除錯能力進一步提升
2023年3月GitHub 發表 Copilot X 構想將 AI 聊天、文件說明及程式碼審查整合到開發流程
2023年4月Amazon CodeWhisperer 正式推出雲端與企業開發環境加入 AI 程式助理
2023年Cursor 開始發展AI 深度整合至程式編輯器，推動 AI 原生開發環境

這個階段最重要的三項改變：

  1. 從程式碼補全到程式碼生成：AI 不只是預測下一行，也能依照需求撰寫完整函式。
  2. 從程式碼生成到程式解釋：工程師可以詢問 AI 某段程式的用途及錯誤原因。
  3. 從單純編輯器到對話式開發：使用者可以透過自然語言與 AI 討論程式設計。

例如，使用者只要輸入：

「請幫我寫一個網頁，可以輸入學生姓名與成績，並自動計算平均分數。」

AI 就能產生 HTML、CSS 與 JavaScript 程式碼。

第六階段：AI 原生開發環境與程式協作（2023～2024年）

這個階段的特色，是 AI 不再只是附加在編輯器中的工具，而是逐漸成為整個軟體開發環境的核心。

時間重要事件發展意義
2023年GitHub Copilot Chat 推出預覽開發者可以透過對話詢問程式問題
2023年Amazon CodeWhisperer 持續擴展AI 程式協助整合雲端開發流程
2023年Cursor 發展 AI 原生編輯器AI 能理解專案中的多個程式檔案
2024年Claude 3.5 Sonnet 發表程式碼生成、分析及視覺理解能力提升
2024年Anthropic 推出 Artifacts使用者可在對話環境中檢視及修改生成內容
2024年GitHub Copilot Edits 發展AI 開始協助修改多個程式檔案
2024年Replit Agent 推出使用者可透過自然語言要求 AI 建立應用程式
2024年Windsurf 編輯器推出強調 AI 理解整個專案及連續執行開發任務
2024年MCP（Model Context Protocol）提出建立 AI 模型連接外部工具與資料來源的標準化方式

這個階段的重要觀念：

  • AI 能夠理解整個程式專案，而不只是單一程式碼片段。
  • AI 能夠同時修改多個檔案。
  • AI 能夠閱讀錯誤訊息，提出修改建議。
  • AI 開始與資料庫、終端機及外部開發工具整合。
  • 自然語言逐漸成為軟體開發的重要操作介面。

其中，MCP（Model Context Protocol）尤其值得注意。它讓 AI 可以透過標準化方式連接檔案、資料庫、開發工具及其他外部服務，為後來的 AI Agent 發展建立重要基礎。

第七階段：AI Agent 與自主程式開發（2025年）

重要轉折

2025 年是 AI 程式設計從「協助工程師寫程式」進一步走向「AI 自主執行開發任務」的重要階段。

過去，AI 通常產生一段程式碼，接著由人類複製、貼上及測試。

現在，AI Agent 可以在授權的環境中讀取專案、修改檔案、執行程式、檢查錯誤，再根據結果繼續修正。

時間重要事件發展意義
2025年2月Anthropic 推出 Claude Code 研究預覽AI 能透過終端機操作程式專案
2025年2月Andrej Karpathy 提出 Vibe Coding 一詞描述以自然語言及直覺式對話與 AI 協作開發的方式
2025年2月GitHub Copilot Agent Mode 推出預覽AI 能夠規劃及執行多步驟程式修改
2025年4月OpenAI 推出 Codex 雲端軟體工程代理服務AI 可以在雲端環境執行較長時間的程式開發任務
2025年5月GitHub 推出 Copilot Coding AgentAI 能夠處理 GitHub Issue、修改程式並提出 Pull Request
2025年5月OpenAI Codex CLI 開源開發者可以在終端機中使用 AI 操作本機程式專案
2025年6月Google 推出 Gemini CLI以終端機方式整合 AI 與開發工具
2025年MCP 生態系逐漸擴大AI Agent 能連接更多外部工具及服務
2025年多代理人協作模式受到重視不同 AI Agent 可以分工處理程式、測試及審查

Vibe Coding 是什麼？

Vibe Coding 可以翻譯為「氛圍式程式設計」或「直覺式 AI 協作編程」。

這種方式不要求使用者從頭手寫所有程式，而是先描述想要的功能，再透過與 AI 不斷對話，逐步調整成果。

例如：

  • 「幫我製作一個世界歷史時間軸。」
  • 「增加朝代篩選功能。」
  • 「加入可以點擊展開的歷史事件。」
  • 「改成適合平板電腦閱讀的版面。」
  • 「請檢查程式錯誤並修正。」

AI 會依照這些要求逐步修改程式。

不過，Vibe Coding 並不代表不需要懂程式。當系統越複雜，越需要人類檢查程式正確性、資料安全與整體架構。

第八階段：多代理人協作與 AI 軟體工程（2026年）

新一代發展方向

2026 年的 AI 程式設計，重點已不只是生成程式碼，而是如何讓多個 AI Agent 分工合作，完成較大型、較複雜的軟體專案。

時間重要發展發展意義
2026年AI Agent 多任務協作持續成熟多個代理人可以同時處理不同開發工作
2026年AI 自動測試與程式碼審查深化AI 不只撰寫程式，也協助驗證與檢查成果
2026年AI 開發環境與雲端電腦整合AI 可以在隔離環境中執行完整開發流程
2026年Harness Engineering 受到重視開始重視如何設計工具、規則、測試與執行環境，讓 AI Agent 穩定工作
2026年多代理人與工作流程編排發展可以安排不同 AI 分別擔任規劃、程式撰寫、測試及審查角色

2026 年的發展可以從 OpenAI Codex 的產品演進觀察：AI 已經從程式碼生成工具，逐漸成為能夠處理較長期、跨檔案軟體工作的工程協作者。

二、AI 程式設計工具的發展比較

AI 程式設計的歷史，也可以透過代表性工具來理解。

1. GitHub Copilot（2021）

程式碼助理

以即時程式碼補全起家，後來增加對話、程式碼修改及 Agent 功能。

2. ChatGPT（2022）

對話式程式設計

使用自然語言要求 AI 撰寫、解釋、修改及除錯程式。

3. Cursor（2023）

AI 原生編輯器

將 AI 深度整合至程式編輯器，協助理解專案、修改多個檔案及開發功能。

4. Replit Agent（2024）

自然語言建站

使用者描述需求，AI 協助建立應用程式、編寫程式及部署。

5. Claude Code（2025）

Agent 開發

能夠閱讀程式專案、操作終端機、修改檔案及執行測試。

6. OpenAI Codex（2025）

雲端軟體工程

能夠在隔離環境中處理程式開發任務，並行執行不同工作。

六、AI 程式設計發展史的六大轉折

1950～1980年代：讓機器學會推理

從符號邏輯、專家系統及自動程式生成開始探索。

1990～2000年代：讓機器從資料學習

機器學習、程式碼分析與自動化開發工具逐漸成熟。

2010～2019年：讓機器理解程式碼

深度學習、Transformer 與程式碼模型推動技術突破。

2020～2023年：讓 AI 成為程式助理

Codex、Copilot、ChatGPT 改變程式設計方式。

2023～2024年：讓 AI 參與整個開發環境

AI 原生編輯器與專案級程式修改逐漸普及。

2025～2026年：讓 AI 成為軟體工程協作者

AI Agent、多代理人協作、自動測試及雲端開發成為重要方向。

七、延伸研究：AI 程式設計的未來發展

未來值得關注的五個方向：

  1. 自然語言程式設計（Natural Language Programming）：人類以文字或語音描述需求，AI 將其轉換成程式。
  2. 自主軟體工程（Autonomous Software Engineering）：AI 能獨立完成更多開發、測試及維護工作。
  3. 多代理人協作（Multi-Agent Development）：不同 AI 分別負責設計、開發、測試與審查。
  4. 自我修復軟體（Self-Healing Software）：系統能自動發現問題、提出修正並驗證。
  5. AI 與低程式碼平台結合（AI + Low-Code）：讓沒有專業程式背景的人也能建立較完整的應用程式。

1950s → 2026

  1. 人類設計規則：AI 依照人類設定的知識與邏輯運作。
  2. 機器學習：AI 開始從資料中找出規律。
  3. 深度學習：AI 開始理解更複雜的資料與程式結構。
  4. 生成式 AI：AI 能依照需求產生程式碼。
  5. AI Agent：AI 能規劃及執行多步驟程式開發工作。
  6. 多 Agent 協作：人類負責目標與品質，多個 AI 協同完成軟體工程任務。
